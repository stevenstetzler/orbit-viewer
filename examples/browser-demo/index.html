Load from the local kernel proxy

Served by npm run serve-example -- each of these streams straight from NAIF on demand, so even a multi-gigabyte kernel costs a few hundred KB to open.

    1. Get a kernel

    NAIF's server doesn't send CORS headers, so this page can't fetch() a kernel directly from naif.jpl.nasa.gov -- browsers block cross-origin reads without them, regardless of caching. Download once (native browser download, unaffected by CORS since it's not read by JS), then pick the file below. Nothing is ever uploaded -- the file stays local and only the small byte ranges spiceJS needs are read from it.

    Download de440s.bsp (~32 MB)

    3. Time window

    ±30 d

    How much time around now to prefetch, and the span each orbit-arc line covers around wherever the "Reference epoch" slider below is currently pointing. Widening this fetches more of the file (still only the bytes needed for these bodies) -- already-fetched bytes are never re-fetched.

    4. Reference epoch

    –

    Position within the time window above (UTC) -- each orbit-arc line re-centers on this epoch as it moves, always spanning the full ±window above (loading more bytes on demand if you scrub somewhere not prefetched yet, rather than clipping the arc short there).

    Bodies shown

    Click a body to center the view on it (non-rotating ECLIPJ2000, same as Control+Click). Alt/Option+Click locks the view to that body's own rotating IAU_<BODY> frame instead -- orbit-arc lines are hidden there (a coarse time sample can't meaningfully trace a fast rotation; live marker positions stay exact regardless). Shift+Click enters a "precise" single-body mode: centers on just that body and its real satellites (if any), true-to-scale by its own physical radius rather than the whole-system AU scale. Click the active body again (same modifier) to go back.
