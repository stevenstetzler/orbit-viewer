    1. Get a kernel

    NAIF's server doesn't send CORS headers, so this page can't fetch() a kernel directly from naif.jpl.nasa.gov -- browsers block cross-origin reads without them, regardless of caching. Download once (native browser download, unaffected by CORS since it's not read by JS), then pick the file below. Nothing is ever uploaded -- the file stays local and only the small byte ranges spiceJS needs are read from it.

    4. Add a custom kernel

    Layer bodies from your own .bsp onto this session -- e.g. an asteroid/comet or mission trajectory kernel not in the catalogue above. Structurally scanned first (a couple of small byte-range reads, same as "2. Load a kernel"), so you can pick which of its bodies to add before any real data is fetched.

    5. Fetch from JPL Horizons

    Fetch a real small-body/comet trajectory straight from JPL Horizons and add it exactly like "4. Add a custom kernel" above -- a name (Ceres, Apophis), a numbered designation (99942, or a comet like 1P), or a provisional designation (1999 AN10) all work. Looked up first against JPL's Small-Body Database; if more than one object matches, you'll get a list to pick from. Needs the local proxy running (neither API sends CORS headers) -- same requirement as the kernel catalogue above.

      View controls

      Center and Frame pick bodies independently (e.g. positions relative to Earth, oriented as Jupiter rotates is a valid combination); Rotating decides whether Frame's own IAU_<BODY> orientation is actually used, or the fixed, non-rotating ECLIPJ2000 instead. Orbit switches each shown body's arc between an idealized two-body Ellipse (exact right now, always closed) and its real sampled Trajectory over one orbit of whichever body you're centered on -- auto-selected (Ellipse at the Solar System Barycenter, Trajectory anywhere else) but changeable any time. Period (Trajectory only) picks what "one orbit" means per body: Sidereal (each body's own real orbital period) or Synodic (each body's period relative to Center instead -- how long its position relative to here takes to repeat). Position scale/Radius scale pick how km become scene units, independently -- Linear is true-to-scale, Sqrt compresses large values (so e.g. Neptune's real distance from the Sun doesn't dwarf everything closer in). Auto-selected per view (whole system: Linear position/Sqrt radius; a single body's own system: Linear/Linear, sized so its smallest member stays visible) but changeable any time, same as Orbit/Period. Each row below also has Look (aim the camera at that body without changing any of the above) and From (set Center and Frame to that body at once).
